# HackNight 7 - Maintainer Checklist

Ensure your repository is ready for HackNight 7 by following this comprehensive checklist.

---

### 🧩 1. Basic Checklist

#### README.md
- [ ] What the project does and its purpose
- [ ] What the project is built on (tech stack)
- [ ] How people can build and run the project locally (and test if needed)
- [ ] Maintainer(s) in charge (with GitHub link)
- [ ] Clear setup and contribution instructions
- [ ] Link or mention of `CONTRIBUTING.md`
- [ ] License details (mention the repo is open-source)

#### CONTRIBUTING.md
- [ ] Basic structure of the project
- [ ] PR guidelines (keep it simple and clear)
- [ ] Issue/Bug guidelines (optional)
- [ ] Any rules specific to your project
- [ ] Coding or formatting conventions (if any)

#### LICENSE
- [ ] Any basic open-source license will do (if unsure, use MIT License)

#### CODE_OF_CONDUCT.md
- [ ] CODE_OF_CONDUCT.md included (optional but encouraged)

#### Repository Tags
- [ ] Must include `hacktoberfest` label
- [ ] Must include `hacknight-2025` label

---

### 🧾 2. Issues

- [ ] At least 4 initial issues created
- [ ] At least 2 issues solvable within an hour
- [ ] Every issue must include:
  - [ ] Explanation of the issue
  - [ ] Possible fix or approach (optional)
  - [ ] Relevant logs or screenshots (if any)
  - [ ] Maintainer's notes or insights
  - [ ] Resources or references related to the issue
  - [ ] Bounty Points assigned to the issue

---

### 💰 3. Points System

- [ ] Understand Bounty Points (0-50: minimal, 250-500: medium, 800-1500: major)
- [ ] Understand Brownie Points (10-20 pts for exceptional work, up to 50 pts in rare cases)
- [ ] All issues have appropriate bounty points assigned

---

### 📝 4. Final Notes

- [ ] DO NOT delete or intentionally break features before the hack
- [ ] Keep issues practical and fair
- [ ] Well-structured README and CONTRIBUTING files
- [ ] Maintainers should be available on Discord during HackNight
